The root orchestrates the app entry point `src/index.ts` (declared in `wrangler.jsonc`) which exposes a Hono server backed by Better Auth for authentication and Drizzle ORM over D1 for persistence. `drizzle.config.ts` generates SQL migrations into `./drizzle`, which Wrangler references as `migrations_dir` so `wrangler d1 migrations apply` runs them against both local and remote D1 databases. The same `./drizzle` directory is consumed at test-config time by `vitest.config.ts` via `readD1Migrations`, injecting migrations into an isolated per-run D1 instance through the `@cloudflare/vitest-pool-workers` pool so tests exercise the real workerd runtime with the actual schema. Environment bindings (`DB`, `MEDIA`, `APP_ENV`, secrets) are declared centrally in `wrangler.jsonc` and re-used by both development (`wrangler dev`) and testing (`vitest`). TypeScript path aliases (`@/* → ./src/*`) and shared types from `@cloudflare/workers-types` are configured once in `tsconfig.json` for all child modules.
