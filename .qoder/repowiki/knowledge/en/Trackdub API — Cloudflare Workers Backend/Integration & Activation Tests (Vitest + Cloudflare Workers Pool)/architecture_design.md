Tests are organized as one file per concern under `test/`, all executed inside the Cloudflare Workers Vitest pool (`cloudflare:test`). A global setup hook in `apply-migrations.ts` uses Vitest's `beforeAll` to call `applyD1Migrations(env.DB, env.TEST_MIGRATIONS)` once per run, giving every test a fresh D1 instance. Each test file imports the real `@/index` Hono app and constructs a `Bindings` object by casting `env` from `cloudflare:test`. End-to-end assertions go through `app.request(path, init, bindings)`, while middleware-only scenarios (auth, error) spin up a minimal synthetic Hono app that wires only the relevant middleware plus `onError`. The `activation/` subdirectory contains dedicated tests for the activation Worker, with its own helpers (`helpers.ts`) that seed licenses directly into D1 and a standalone `test-keys.ts` module holding ephemeral ECDSA P-256 keys safe to import in both Node and workerd contexts. Type augmentation for the test environment lives in `env.d.ts`, which extends `Cloudflare.Env` with `TEST_MIGRATIONS: D1Migration[]` so tests compile without a prior `wrangler types` step.
